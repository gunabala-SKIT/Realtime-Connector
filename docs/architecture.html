Production Architecture & Data Flow

This is the architecture the phased build converges on. It traces one path end to end: a camera frame is decoded, sampled, and run through the AI worker; a person becomes a track, a face becomes a 512-dimension embedding, the embedding resolves to a business identity, the identity produces a structured event, and a matching rule raises an alert that reaches an operator in near-real time. Storage, deployment, and the MVP-to-production path follow.

The production flow

camera → ingestion → AI worker → identity & events → rules → alerting → application

Each tier is an independently scalable service. Video ingestion, AI inference, and event processing are separated deliberately so the platform can grow from one camera to many by adding workers to a single tier rather than rebuilding. The teal path is live video-derived data moving forward; dashed grey lines are reads and writes against shared stores.

Inside the AI worker: one frame

per sampled frame, per track

Detection and tracking run once per frame. Face detection, the quality gate, and recognition run per active track. The quality gate is the pivot: a track with no usable face is UNVERIFIED — the system holds the track but makes no identity claim, which is what keeps false security alerts down.

One person, one pass

event lifecycle · entrance camera

A concrete walk-through of the flow above, for a registered employee. Times are illustrative, against the Nominal test conditions in the acceptance-criteria document.

  1. T+0.0s Person crosses the door line. YOLO detects them; BoT-SORT opens track 101. No face yet → UNVERIFIED. No event, no claim.
  2. T+0.4s Face becomes large and frontal enough to pass the quality gate. ArcFace produces a 512-d embedding.
  3. T+0.9s k-NN against the employee gallery returns a top-1 cosine score above T → RECOGNIZED as Employee A. The event engine emits one identity_recognized event with camera, track, employee, confidence, timestamp, and a snapshot reference.
  4. T+1–8s The person keeps walking. track 101 stays stable; the face drops out of gate quality intermittently but the identity is held. No new events — deduplication suppresses them because (camera, track, status) is unchanged.
  5. T+8.2s Person leaves the frame. After 5s with no detection matched to track 101, the track closes. A later re-entry is a new track and a new event.

For an unregistered person the first three steps are identical until the k-NN score falls below T → UNKNOWN. If ≥ 5 of the last 8 gate-passed frames agree, and a rule such as identity = UNKNOWN on the entrance camera matches, the alert manager raises a high-priority alert and the notifier pushes it to every connected operator.

Deployment topology

on-premise · single host · MVP baseline

The MVP runs every service as a container on one GPU host on the local network, with cameras on their own segment. This gives predictable latency and keeps biometric data on-site. The same compose file scales out by replica count before it ever needs a second host.
